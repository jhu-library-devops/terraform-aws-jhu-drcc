# jev-training

Optional AWS infrastructure for **fine-tuning LISA**, the custom Jev decider
variant. It does **not** run training — that is a SageMaker training job
launched by the Jev project's `sagemaker_launch.py`. This module provisions the
two things that job needs:

- a private, encrypted, versioned **S3 bucket** for labelled data (`data/`) and
  model artifacts (`artifacts/`), with a lifecycle rule to expire old checkpoints;
- a least-privilege **SageMaker execution role** scoped to that bucket (plus
  CloudWatch Logs and ECR pull for the training container).

It is **disabled by default** (`training_enabled = false`): the serving path
(`jev-agentcore`) does not depend on it, so a plain `tofu apply` of the app env
provisions no training resources until you opt in. It is provider-agnostic and
inherits the `aws` provider (region, profile, default tags) from the calling root.

## Usage

```hcl
module "jev_training" {
  source = "git::https://github.com/jhu-library-devops/terraform-module-library.git//modules/jev-training?ref=jev-training-v0.1.0"

  namespace   = "drcc-ai"
  environment = "aiops"

  training_enabled         = true          # opt in
  artifact_expiration_days = 180           # expire old checkpoints
  # artifacts_bucket_name  = "my-unique-bucket"   # optional override
}
```

The role ARN and bucket prefixes are outputs — thread them into the launcher:

```bash
python sagemaker_launch.py --tier lora \
  --train  "$(tofu output -raw training_data_prefix)train.jsonl" \
  --eval   "$(tofu output -raw training_data_prefix)eval.jsonl" \
  --role-arn "$(tofu output -raw training_role_arn)" \
  --output "$(tofu output -raw training_artifacts_prefix)" \
  --profile drcc-ai
```

## Notes

- **Provider & backend belong to the caller.** This module has neither, by design.
- All resources are `count`-guarded on `training_enabled`; off by default so it
  adds nothing to the serving deploy until explicitly enabled.
- The bucket blocks all public access, encrypts with SSE-KMS (bucket key), and
  versions objects; `artifacts_force_destroy` stays `false` so a stray `destroy`
  cannot wipe a non-empty artifact bucket in a shared account.
- The SageMaker role can read/write **only** this bucket — it is not an admin
  role. Fine-tuning touches no Jev serving resources.
