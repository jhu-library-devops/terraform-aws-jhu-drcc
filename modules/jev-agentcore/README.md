# jev-agentcore

Surrounding AWS infrastructure for a **Jev** decision agent whose model runs on
Amazon Bedrock AgentCore Runtime. This module does **not** deploy the AgentCore
runtime itself — that is done by the AgentCore CLI in the consuming project
(e.g. `jev-decider`). This module wires up the pieces around it:

- an **invoke IAM policy** (`bedrock-agentcore:InvokeAgentRuntime`) to attach to callers;
- an optional **warm-up ping** (EventBridge Scheduler + Lambda) for Posture A;
- an optional **decision log** DynamoDB table (idempotency + audit).

It is provider-agnostic: it declares `required_providers` only and inherits the
`aws` provider (region, profile, default tags) from the calling root. Supply the
runtime ARN produced by `agentcore deploy`.

## Usage

```hcl
module "jev" {
  # Pin to a released tag of this library:
  source = "git::https://github.com/jhu-library-devops/terraform-module-library.git//modules/jev-agentcore?ref=jev-agentcore-v0.1.0"

  namespace           = "drcc-ai"
  environment         = "aiops"
  decider_runtime_arn = "arn:aws:bedrock-agentcore:us-east-1:390157243417:runtime/JevDeciders_jev-XXXXXX"

  # Posture A (defaults shown)
  warmup_enabled             = true
  warmup_timezone            = "America/New_York"
  warmup_schedule_expression = "cron(55 7 ? * MON-FRI *)"

  decision_log_enabled = true
}
```

## Notes

- **Provider & backend belong to the caller.** This module has neither, by design.
- The warm-up Lambda source is bundled at `lambda/warmup/handler.py` and zipped
  via the `archive` provider at plan time (`${path.module}`), so the module is
  self-contained when used by `source = "..."`.
- Toggling `warmup_enabled` / `decision_log_enabled` off removes those resources
  cleanly (count-guarded); the invoke policy is always created.
