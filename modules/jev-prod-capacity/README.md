# jev-prod-capacity

Supporting AWS infrastructure for the **`jevprod`** AgentCore runtime — a
dedicated, **provisioned** compute posture for Jev on a `c7g.4xlarge` on-demand
fleet, distinct from the scale-to-zero Posture-A `jev` runtime.

An AgentCore runtime has no vCPU/memory knob: a plain runtime is a fixed
2 vCPU / 8 GB microVM. Bigger, dedicated compute comes from a **capacity
provider** (an EC2-backed fleet), and a capacity provider requires an operator
IAM role and an EC2 instance profile that do not otherwise exist. This module
creates exactly those, least-privilege, plus one egress-only security group. The
**capacity provider and the `jevprod` runtime themselves are declared in
`agentcore/agentcore.json`** and consume this module's outputs.

- **operator role** — assumed by `bedrock-agentcore` to launch/terminate the
  fleet in the given subnets; `iam:PassRole` is scoped to the instance role only.
- **instance role + profile** — what the `c7g.4xlarge` instances run as: ECR
  pull, CloudWatch logs, SSM core. Nothing else.
- **security group** — egress only (ECR, base-model download, logs); no inbound
  (AgentCore reaches the runtime through its own managed path).

It is **disabled by default** (`prod_capacity_enabled = false`): this is an
always-on-cost posture (~$0.58/hr on-demand ≈ ~$420/mo for one 24×7 instance),
so a plain app-env apply provisions nothing here until you opt in. VPC and
subnets are **reused** (passed in); the module creates no networking beyond the
security group. Provider-agnostic — inherits the `aws` provider from the caller.

## Usage

```hcl
module "jev_prod_capacity" {
  source = "git::https://github.com/jhu-library-devops/terraform-module-library.git//modules/jev-prod-capacity?ref=jev-prod-capacity-v0.1.0"

  namespace   = "drcc-ai"
  environment = "aiops"

  prod_capacity_enabled = true
  vpc_id                = "vpc-xxxxxxxx"                 # reuse an existing VPC
  subnet_ids            = ["subnet-aaaa", "subnet-bbbb"] # private, multi-AZ
}
```

Then thread the outputs into `agentcore/agentcore.json`'s `capacityProviders[0]`:

```bash
tofu output -raw prod_operator_role_arn        # -> operatorRoleArn
tofu output -raw prod_instance_profile_arn     # -> launchParameters.instanceProfileArn
tofu output -raw prod_fleet_security_group_id  # -> vpcConfiguration.securityGroups[0]
```

…then `agentcore deploy` creates the capacity provider + the `jevprod` runtime.

## Notes

- **Provider & backend belong to the caller.** This module has neither, by design.
- All resources are `count`-guarded on `prod_capacity_enabled`; off by default.
- ARM64 (`LINUX_ARM64` / Graviton) matches the existing `qnnpack` arm64 runtime
  image — no rebuild. A GPU posture would need the bf16 build + a CUDA image.
- On-demand by choice: the fleet backs a live decision endpoint, so it is not on
  Spot (a reclaim would drop a serving instance and force a ~5-min cold start).
  Spot belongs on the fine-tuning jobs (`jev-training`), not here.
